# 01-01 PLAN: Phase 1 — Hardening & Security Fixes

## Goal
Close the highest-severity security gaps and correctness risks identified in the codebase (CSP hardening, restricted batch writes, inventory negative stock prevention, structured DB error returns, and secure session role resolution) without adding features.

## Requirements Covered
- **SEC-01**: CSP in `index.html` removes `unsafe-inline` from script-src and style-src
- **SEC-02**: `db:executeBatch` rejects writes to `licence_data` and `security_config` from the renderer
- **SEC-03**: `db:executeBatch` validates allowed columns per table before writing
- **COR-01**: `db:processSale` aborts when `stockLevel < item.quantity` (no negative stock)
- **COR-02**: DB read handlers return structured `{ success, data, error }` instead of masking errors as `[]`/`null`
- **ACC-01**: User role resolved from authenticated session, not client-controlled localStorage

## Tasks

### T1: Tighten Content Security Policy (`index.html`)
- **Requirement:** SEC-01
- **Description:** Remove `unsafe-inline` from `script-src` and `style-src` in `index.html` CSP meta tag. Add nonces/hashes or refactor any inline scripts if needed so the app loads securely without breaking.
- **Files to modify:** `index.html`, `src/app.js` (if inline script exists)
- **Estimated Effort:** Medium (1-2 hours)
- **Verification Criteria:** App loads successfully; console shows no CSP violations; `unsafe-inline` absent from script-src/style-src.

### T2: Secure `db:executeBatch` Table & Column Guards (`controllers.js`)
- **Requirements:** SEC-02, SEC-03
- **Description:** Update `db:executeBatch` in `electron/database/controllers.js` to:
  1. Reject any batch write operations targeted at sensitive tables (`licence_data`, `security_config`).
  2. Validate that every column in `data` for allowed tables is present in a strict per-table column whitelist.
- **Files to modify:** `electron/database/controllers.js`
- **Estimated Effort:** Medium (2 hours)
- **Verification Criteria:** Attempted writes to `licence_data`/`security_config` or disallowed columns throw an error / are rejected. Vitest unit tests added for `executeBatch` validation.

### T3: Stock Availability Guard in `db:processSale` (`controllers.js`)
- **Requirement:** COR-01
- **Description:** Update `db:processSale` in `electron/database/controllers.js` to pre-check current `stockLevel` within the database transaction for each item in the sale. Abort and rollback the transaction if `stockLevel < item.quantity`.
- **Files to modify:** `electron/database/controllers.js`
- **Estimated Effort:** Small (1 hour)
- **Verification Criteria:** Selling items with insufficient stock throws an explicit error and rolls back transaction. Unit test verifies oversell rejection.

### T4: Structured Error Returns from Database Read Handlers (`controllers.js`)
- **Requirement:** COR-02
- **Description:** Update DB read IPC handlers in `electron/database/controllers.js` (`db:getProducts`, `db:getTransactionsSince`, `db:getPendingCheques`, `db:getDoc`, etc.) to return structured `{ success: boolean, data: any, error: string | null }` instead of silently returning empty arrays `[]` or `null` on failure.
- **Files to modify:** `electron/database/controllers.js`, any preload/renderer callers expecting specific return structures.
- **Estimated Effort:** Medium (2 hours)
- **Verification Criteria:** Read failures return `{ success: false, error: '...' }`; callers handle structured response correctly.

### T5: Secure User Role Resolution from Authenticated Session (`LocalAuthService.js` / `controllers.js` / preload)
- **Requirement:** ACC-01
- **Description:** Ensure user role is determined from the secure authenticated session (via `LocalAuthService` / main process session state) rather than trusting client-controlled `localStorage` roles.
- **Files to modify:** `electron/services/LocalAuthService.js`, `electron/preload.js`, relevant IPC handlers and UI check logic.
- **Estimated Effort:** Medium (2 hours)
- **Verification Criteria:** Privilege checks rely on main-process session verification rather than client localStorage tampering.

## Dependencies

- T4 touches `electron/database/controllers.js` as well.
- T1 (CSP) and T5 (Auth Role) are independent files (`index.html`, `LocalAuthService.js`, preload).
